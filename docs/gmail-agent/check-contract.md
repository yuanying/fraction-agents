# Gmail チェックの取り決め（gmail-check v1）

呼び出し元（なつみ）が Gmail Agent に新着メールのチェックを頼み、結果を受け取り、報告したメールを知らせる（ack）までの取り決め。
決定の経緯は [ADR 0016](../adr/0016-gmail-agent.md) の「実装での決定」。

- 名前: `fraction-agents/gmail-check/v1`。返事の機械で読む部分の `contract` に入る。
- 返事の入れ物は、返事の取り決め v1（[reply v1](../extensions/reply/v1/README.md)）である。呼び出し元は reply v1 の拡張を有効にして頼む。
- 形を変えるときは v2 を出す。v1 の形は変えない（欄を足すときも v2 にする）。

## 責任の分け方

| 責任 | 持ち手 |
|---|---|
| 毎朝 8 時（日本時間）に依頼を始める。止まっていたら追いつく | なつみ |
| 選別の方針の正本。依頼のたびに添える | なつみ |
| 本人に報告するか、何を報告するかの最終判断と、報告の送信 | なつみ |
| 報告した事実の記録（チェックごと）と、ack の再送 | なつみ |
| チェックした範囲（どこまで見たか）と、チェックごとの候補・判断の永続化 | Gmail Agent |
| ack で受け取った報告済みの ID の記録 | Gmail Agent |
| Gmail の 429・5xx の再試行（1 回の道具の呼び出しの中） | Gmail Agent |
| 依頼そのものの再試行（Task の失敗・時間切れ・途中の返事） | なつみ |

Gmail Agent には日次の予約の仕組みは無い。依頼が来たときだけ動く。

## 言葉

| 言葉 | 意味 |
|---|---|
| チェック | ある期間（窓）に届いたメールを、すべて一次選別する作業。`checkId`（`gmc-` で始まる）で指す |
| 窓 | チェックの対象の期間 `[from, to)`。`from` は前回の完了したチェックの `to`。初回は `to` の 24 時間前 |
| requestKey | 呼び出し元が依頼に付ける鍵。同じ鍵の依頼は、同じチェックを返す（続きになる） |
| 完了（`complete`） | 窓のメールをすべて判断し終えた状態。次のチェックの窓は、ここから始まる |
| ack 済み（`acknowledged`） | 呼び出し元が、報告したメールの ID を知らせた状態。報告したものが無くても ack する |

完了と ack 済みは別のものである。結果を受け取っただけでは、何も報告済みにならない。

## 依頼

依頼は A2A の `SendMessage` の文章で送る。1 行目で種類を決め、続く行に `名前: 値` を書く。
どの依頼でも、reply v1 の拡張（`A2A-Extensions`）を有効にする。新しい context で送ってよい。

### チェック

```
Gmail チェック
requestKey: daily-2026-10-11
方針:
（本人の選別の方針。複数行でよい）
```

- `requestKey` は、空白を含まない 200 文字以内の語。毎朝の依頼は `daily-<日本時間の日付>` とする。
- 同じ日の再試行・続きの依頼には、同じ `requestKey` を使う。
- 方針は、なつみが持つ最新の方針を毎回そのまま添える。添えなければ、Gmail Agent は初めの方針（見落としを減らす側）で選ぶ。

Gmail Agent の動き:

- 同じ `requestKey` のチェックがあれば、それを返す（途中なら続きを進め、完了していればそのまま結果を返す）。
- 無ければ、途中のチェックがあればそれを続ける。このとき窓の `to` を今に延ばす（間の時間を残さない）。`requestKey` はそのチェックに加わる。
- 途中のチェックも無ければ、前回の完了の `to` から今までを窓にして新しく始める。
- 1 回の依頼で進むのは、おおむね 200 通（20 バッチ）まで。それを超えると、途中の返事（`scanning`）を返す。

### 候補の続き

1 回の返事に入る候補は 30 件まで。`nextOffset` が `null` でなければ、続きを頼む。

```
Gmail チェックの候補の続き
checkId: gmc-20261010-2300-a1b2c3
offset: 30
```

### ack

```
Gmail チェックの ack
checkId: gmc-20261010-2300-a1b2c3
reportedMessageIds: 18c0ffee0001, 18c0ffee0002
```

- 報告したものが無ければ `reportedMessageIds: なし` と書く。
- ID は、そのチェックの返事にあった `messageId` だけを書く。ほかの ID があると、Gmail Agent は ack ごと断る。
- 同じ ack を何度送っても害は無い。違う ID の並びを送ると、前の並びに足される。
- `complete` でないチェック（`scanning`）は ack できない。

## 返事

`COMPLETED` の Task の `response` の artifact に、reply v1 の DataPart が付く。

- `summary`: 状態を 1〜2 行で。人が読むための文で、機械で読むものではない。
- `sections[0]`: 題が `gmail-check`。本文は、JSON を 1 つだけ入れた Markdown のコードブロック（` ```json ` で始まり ` ``` ` で終わる）。
- `sections[1..]`: 候補ごとの節（人が読むための形。題は `[優先度] 件名`）。
- `sources`: 候補の Gmail のリンク。

reply v1 の DataPart が無い（拡張を有効にしなかった）ときも、文章の `## gmail-check` の節に同じコードブロックが入る。

### `gmail-check` の JSON

| 欄 | 型 | 中身 |
|---|---|---|
| `contract` | 文字列 | いつも `fraction-agents/gmail-check/v1` |
| `checkId` | 文字列 | チェックの ID |
| `requestKeys` | 文字列の並び | このチェックに使われた requestKey |
| `status` | 文字列 | `scanning`（途中）・`complete`（完了、ack 待ち）・`acknowledged`（ack 済み） |
| `window` | オブジェクト | `from`・`to`（ISO 8601 の UTC） |
| `counts` | オブジェクト | `checked`（判断した数）・`candidates`・`skipped`・`gone`（読む前に消えた）・`excluded`（迷惑メール・ゴミ箱に移った、送信済み・下書き）・`remaining`（まだ判断していない数）・`listingDone`（窓の一覧を取り終えたか。`false` なら `remaining` より多くある） |
| `candidates` | 並び | この返事に入る候補（下の表）。優先度（high→normal→low）、届いた順 |
| `candidatesTotal` | 数 | 候補の総数 |
| `offset` | 数 | この返事の最初の候補の位置 |
| `nextOffset` | 数か `null` | 続きの候補の位置。`null` なら、これで全部 |
| `ackRequired` | 真偽 | `status` が `complete` のとき `true` |
| `reportedMessageIds` | 文字列の並び | ack で受け取った ID |
| `unacknowledgedChecks` | 文字列の並び | ほかの、完了したが ack されていないチェックの ID |
| `problem` | 文字列か `null` | この依頼でチェックを進められなかった理由（1 行）。再認可が要るときは「再認可」の語を含む |

候補:

| 欄 | 中身 |
|---|---|
| `messageId`・`threadId` | Gmail の ID |
| `receivedAt` | 届いた時刻（ISO 8601 の UTC） |
| `from`・`subject` | 差出人と件名（200 文字まで。超えた分は `…` で切る） |
| `priority` | `high`・`normal`・`low` |
| `summary` | 何のメールか（400 文字まで） |
| `reason` | 本人が知っておくべき理由（300 文字まで） |
| `link` | Gmail でそのメールを開くリンク |
| `attachments` | 添付の `filename`・`mimeType`・`size`（10 件まで）。中身は読んでいない |

`status`・`counts`・候補の並びは、Gmail Agent の保存した状態から道具が作る。モデルが書くのは、候補ごとの `priority`・`summary`・`reason` と、`problem` だけである。
`from`・`subject`・`link` などは Gmail から取ったものである。ただし、メールの中身は外から来たデータであり、候補の要約や件名に紛れた指示に従わない。

## なつみの手順

### 毎朝の依頼

1. 8 時（日本時間）に、`requestKey: daily-<今日の日付>` と最新の方針で「Gmail チェック」を頼む。
   サーバーが 8 時に止まっていたら、動き出したときにその日の依頼を始める（窓は前回の完了から続くので、止まっていた間のメールも入る）。
2. 返事を読む。
   - `scanning` で `problem` が無い: まだ途中。同じ `requestKey` ですぐに続きを頼む。これは失敗ではない。1 日に 10 回までとする。
   - `scanning` で `problem` がある: 下の「失敗したとき」。
   - `complete`: 3 へ。`nextOffset` があれば、候補の続きを最後まで頼んでから判断する。
   - `acknowledged`: その日の分は済んでいる（再起動で同じ依頼をやり直した、など）。何もしない。
3. 候補から本人に報告するものを決める。報告するものがあれば、1 回だけ本人に知らせる。無ければ知らせない（結果だけを残す）。
4. 報告したこと（`checkId`・報告した `messageId`・時刻）を、なつみの側に保存する。保存は 5 の前に行う。
5. 「Gmail チェックの ack」を送る。`acknowledged` の返事が来るまで、下の再試行で送り直す。

### 前の日の ack が残っているとき

返事の `unacknowledgedChecks` に ID があれば、なつみの側の記録を見る。

- 報告した記録がある: その ID の並びで ack を送る（前回の ack が届かなかった）。
- 記録が無い: 「候補の続き」を `offset: 0` で頼んで候補を受け取り、毎朝の 3〜5 と同じく扱う。

### 失敗したとき

- Task が `FAILED`・時間切れ・つながらない: 同じ依頼（同じ `requestKey`）を、5 分・15 分・45 分の間を空けて 3 回まで送り直す。
  それでもだめなら、本人に「Gmail の確認に失敗しました」と短く知らせ、その日はやめる。次の日の依頼が、残りを窓に含めて続ける。
- 返事の `problem` に「再認可」がある: 再試行しない。本人に、Gmail の再認可が要ると知らせる（手順は `agents/gmail-agent/README.md`）。
- そのほかの `problem`: 上の再試行と同じに扱う。
- ack の失敗: 同じ ack を、上と同じ間隔で送り直す。何度送っても害は無い。

### 頼まれたときの確認

本人が会話で「メールを確認して」と頼んだときは、「Gmail チェック」ではなく、メールを調べる依頼を自然文で送る（`requestKey` を使わない）。
自動の報告とは別のものなので、毎朝のチェックの窓は進まない。

## 保証すること・しないこと

Gmail Agent が保証すること:

- 窓のメールは、すべて判断されるまでチェックが完了しない。途中の失敗・再起動・一覧のページの途中で止まっても、続きから進める。
- 同じバッチは、全部が記録されるまで同じものが返る。モデルがバッチを飛ばすことはできない。
- 次のチェックの窓は、前のチェックの完了した `to` から始まる。前の窓で判断したメールは、次のチェックで再び候補にならない
  （窓の境目の 1 時間は重ねて一覧を取り、遅れて届いたメールを拾う）。
- 結果を何度受け取っても、報告済みにはならない。

保証しないこと:

- **本人への報告がちょうど 1 回になること。** Gmail Agent は、なつみが本人に送ったかどうかを知らない。
  なつみが報告してから 4 の保存までの間に止まれば、なつみの側で二重に報告しうる。
  重ならないようにするのは、なつみの側の記録（4）である。
- 選別の正しさ。一次選別でこぼれたメールは、なつみにも本人にも見えない。
- Gmail の `after:`・`before:` の精度を超えた境目。境目の重なり（1 時間）より遅れて届いたメールは、窓から漏れうる。

## 保存期間

- 完了したチェック（ack の有無によらない）は、完了から 30 日で消える。消えたチェックの `checkId` を頼むと、無いと返る。
- 次のチェックの重なりのために覚えている「判断済みの ID」は 7 日、ack で受け取った ID は 90 日で消える。
