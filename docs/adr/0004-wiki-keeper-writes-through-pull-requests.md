# 0004. Wiki 管理人は PR で書き込み、マージは本人の指示でだけ行う

- Date: 2026-09-22
- Status: Accepted（`raw/` の扱いは ADR 0009 で置き換えた。「まだ決めていないこと」の置き方と強制は ADR 0009 で決めた）

## Context

最初のエージェントは、汎用ホスト（ADR 0002）で作る LLM Wiki の管理人である。
Wiki は本人の Git リポジトリ（llm-wiki）にあり、取り込み・問い合わせ・整理・公開の手順がリポジトリの規約とスキルで決まっている。

Wiki 管理人には、本人、本人が使う Claude、なつみが書き込みを頼む。
これまでなつみの側では、Wiki のチェックアウトをなつみのコンテナにマウントし、なつみが直接 commit と push をする予定だった。

本人が求めているのは、Wiki の変更の中身を PR の単位で見られることである。
書き込みのたびに承認する門番を置きたいわけではなく、多くの依頼では「PR を出して、そのままマージして」と頼むことになる。

## Decision

### 書き込みは PR で出す

- Wiki 管理人は、Wiki への変更をブランチに積み、PR を出す。既定のブランチに直接 push しない。
- 呼び出し元がマージを指示したときだけ、Wiki 管理人がマージまで行う。
  - 1 つの依頼の中で「PR を出してマージまで」と指示する使い方を主に想定する。
  - マージの指示がなければ、PR を出したところで止める。
- PR は承認の関所ではなく、変更を 1 つの単位として後から見るためのものとする。

### context と PR

- Wiki 管理人は、1 つの context（ADR 0002）に 1 つのブランチと 1 つの PR を使う。
- 同じ context の追加の依頼は、同じ PR にコミットを足す。
  「取り込んで」「ここを直して」「マージして」という一連の依頼が、1 つの PR で完結する。

### マージを指示できる呼び出し元

- マージの指示を受け付けるのは、本人と本人が使う Claude（ServiceAccount の `owner`・`claude`）からだけとする。
- なつみからの依頼は、マージの指示が含まれていても PR で止める。なつみの書き込みは、本人が PR で見てからマージする。
- 呼び出し元は、依頼文の中の名乗りではなく、認証で得た名前で判断する（ADR 0003）。

### Wiki の規約を守る

- Wiki 管理人は、llm-wiki のリポジトリの規約とスキルに従う。
- `raw/` と `Permanent-Notes/` は読み取り専用とし、Wiki 管理人は変更しない。

### まだ決めていないこと

- Wiki 管理人の置き方。llm-wiki の clone の持ち方、push と PR 作成に使う資格、PR の出し方。
- マージの可否を、ホストの処理で強制するか、Wiki 管理人への指示で守らせるか。
- その context の PR がマージ済み、または閉じられた後に、同じ context で書き込みを頼まれたときの扱い。

## Consequences

- Wiki のすべての変更が PR として残り、本人は変更を PR の単位で見られる。
- なつみの書き込みは、本人がマージするまで Wiki の既定のブランチに入らない。
- 本人と Claude の依頼は、マージまで一度に頼めるので、PR を挟んでも手間は増えない。
- 1 つの context での直しが 1 つの PR にまとまるので、本人は依頼の流れの単位で変更を見られる。
- なつみのコンテナに Wiki のチェックアウトをマウントし、なつみが直接 commit と push をする形は採らない。なつみは Wiki への書き込みを Wiki 管理人に頼む。
- Wiki 管理人は push と PR 作成の資格を持つ。資格の範囲は、Wiki 管理人の置き方と合わせて決める。
