# 0002. エージェントの中身の作り方

- Date: 2026-09-22
- Status: Accepted

## Context

ADR 0001 で、エージェントは A2A で話す独立したサービスになった。次に、各エージェントの中身をどう作るかを決める。

エージェントの仕事には 2 種類ある。

- Wiki の管理のように、文書を読んで判断し、書き直す仕事。LLM を使う Coding agent がそのまま向いている。
- ウェブ検索の API を呼ぶ、画像生成の CLI（`sdctl`）を呼ぶといった、決まった手順で済む仕事。LLM を挟む必要がない。

エージェントごとに一から作ると、A2A の処理や認証を何度も書くことになる。
一方、決まった手順の仕事まで LLM に通すと、遅く、上限を消費し、結果が揺れる。

なつみ（[yuanying/natsumi](https://github.com/yuanying/natsumi)）は、本人との会話と長期記憶を一本の context に持つので、
閉じ込めと本人の承認を固くしてある。エージェントはそれとは立場が違う。
呼び出し元は、基本的に本人、本人が使う Claude、なつみだけの予定である。

## Decision

### 汎用ホストと専用実装を混ぜる

- 基本は汎用ホストで作る。
  - 汎用ホストは、Coding agent を headless で動かし、A2A で包んだ共通の image である。
  - エージェントごとの違いは、AGENTS.md、スキル、マウントする volume、秘密、使うモデルの設定だけにする。
  - 1 つの Task を 1 つのセッションで処理する。Task をまたいでセッションを使い回さない。
- 決まった手順で済むもの（検索 API、`sdctl` など）は、LLM を挟まない専用の実装にする。
- 汎用ホストと専用実装は、同じ A2A の共通ライブラリを使う。Agent Card、Task の状態、認証（ADR 0003）の扱いを揃える。
- 最初の 1 匹は、汎用ホストで作る Wiki 管理人（ADR 0004）とする。

### 汎用ホストの runtime とモデル

- 汎用ホストの Coding agent は Pi に固定する。なつみと同じ runtime である。
- モデルはエージェントごとに設定で選ぶ。基本は ChatGPT Plus のサブスクリプション経路の GPT とする。
- エージェント用の Plus の認証は、なつみとは別にログインする。
  - 同じログインを共用すると、refresh token のローテーションで一方がもう一方の token を失効させるためである。
- Plus の利用上限はアカウント単位なので、なつみとエージェントで分け合うことになる。
- Codex App Server を包む専用エージェント（ウェブ検索など）は、専用実装の候補として残す。採るかどうかはまだ決めていない。

### 閉じ込めの強さ

- エージェントの閉じ込めと承認は、なつみほど固くしない。
  - 呼び出し元が本人・本人経由の Claude・なつみに限られ、誰が呼んだかは認証で分かる（ADR 0003）。
  - エージェントは末端で、他を呼ばない（ADR 0001）。
- エージェントに見せるもの・させることは、マウントと秘密で絞る。そのエージェントの仕事に要るものだけを渡す。

## Consequences

- 新しいエージェントの多くは、AGENTS.md とスキルと設定を書くだけで足せる。image は共通のまま使える。
- 決まった手順の仕事は LLM を通らないので、速く、結果が揺れず、Plus の上限を消費しない。
- なつみとエージェントが Plus の上限を分け合う。エージェントを多く使うと、なつみが上限に当たりやすくなる。
- ログインを分けるので、エージェント用の認証情報の更新と失効を、なつみとは別に管理する必要がある。
- 閉じ込めを緩くするので、エージェントが呼び出し元の依頼文に誘導されて、マウントされた範囲の中で想定外の操作をする余地は残る。
  その範囲を小さく保つのは、エージェントごとのマウントと秘密の渡し方である。
- 1 Task = 1 セッションなので、Task をまたいだ文脈は持たない。続きの仕事は、呼び出し元が必要な情報を依頼に含める。
