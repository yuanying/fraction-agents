# 0012. 画像の成果物は汎用ホストが保存し、URI の artifact で返す

- Date: 2026-09-26
- Status: Accepted（ADR 0001 の「成果物は URI で渡す」の具体化）

## Context

ADR 0001 は「画像などの成果物は、エージェントが自分の volume に置き、取得できる URI を A2A の artifact として返す」と決めた。
取得にも認証を掛け、保持期間はエージェントごとに決める、というところまでで、形は決めていなかった。

汎用ホスト（ADR 0007）は、Pi の最後の返事の文を `response` という名前のテキストの artifact で返すだけだった。
ウェブを調べるエージェントがスクリーンショットを呼び出し元（なつみ）に渡したくなり、形を決める必要が出た。

- 画像を作るのは Pi の中のツール（ブラウザなど）である。ホストは A2A の側にいて、Pi のツールの中身を知らない。
- なつみは、受け取った画像を自分の作業環境に取り込み、本人に見せる。取り込むかどうか、どれを取り込むかは、なつみの側で決める。
- 呼び出し元は A2A 1.0 を公式の SDK で話す。

## Decision

### 返し方

- タスクが完了したとき、テキストの artifact（今までどおり、最初）の後に、画像ごとに artifact を 1 つ足す。
  - parts は URL の part 1 つ。A2A 1.0 の Part の `url` に取得先、`mediaType` に画像の形式、`filename` に表示用の短い名前を入れる。
  - artifact の `description` に、何の画像かを 1 行で入れる。
  - 画像が無ければ、返事は今までと同じになる。
- 取得先は、`publicUrl` と同じ origin の `/artifacts/<ID>` とする。
  - ID はホストが乱数で振る（16 進 40 文字）。推測できないが、認証の代わりにはしない。
- 形式は PNG・JPEG・WebP だけとする。拡張子や申告ではなく、ファイルの中身（先頭のバイト）で判定する。
- 1 枚は 10 MiB まで、1 つのタスクで 8 枚まで。超えたもの、形式の違うものは返さない。
- 失敗・取消で終わったタスクの画像は返さずに捨てる。答えを待っている間（`INPUT_REQUIRED`）は捨てない。

### 取得

- `GET /artifacts/<ID>` は、A2A の呼び出しと同じ認証を要る（ADR 0003）。token が無い・違うときは 401、許していない ServiceAccount は 403。
- 画像を返すのは、そのタスクを送った呼び出し元にだけとする。他の呼び出し元には、知らない ID と同じ 404 を返す。
  context と Task が呼び出し元ごとに閉じている（ADR 0002）のと揃える。
- 知らない ID、期限を過ぎた ID は 404。本文は画像そのもので、`Content-Type` と `Content-Length` を付ける。

### 保持

- 画像はホストのデータ領域（PVC）の `artifacts/` に置き、ID と持ち主と形式を SQLite に記録する。ホストを再起動しても取れる。
- 保持期間は、作ってからの時間で数える。既定は 7 日で、設定の `artifactRetentionSeconds` で変えられる。
- 期限を過ぎたものは、掃除を待たずに 404 にし、定期の掃除でファイルと記録を消す。

### Pi からホストへの受け渡し

- Pi のツールが画像を成果物にする道は、専用のツール `attach_image` とする。fraction-agents の Pi パッケージの拡張で出す。
  - モデルが、画像のファイルのパスと、何の画像かの 1 行を渡して呼ぶ。スクリーンショットは、まずファイルに撮ってから添える。
  - ツールは、その場で形式・大きさ・枚数を確かめ、だめならモデルに理由を返す。ホストも受け取るときにもう一度確かめる。
- ホストは context ごとに受け渡しの場所（outbox）を決め、環境変数 `FRACTION_AGENTS_ARTIFACT_OUTBOX` で Pi に渡す。
  ツールは画像をそこに写し、名前と説明を書いた小さな JSON を並べて置く。タスクが終わったら、ホストがそれを引き取って空にする。
- ホストの外で Pi を動かしたとき（環境変数が無いとき）は、ツールを出さない。

## Consequences

- どのエージェントも、Pi パッケージを読むだけで画像を返せる。ホストは Pi のツールの中身（ブラウザの種類、結果の形）を知らなくてよい。
- 画像を返すかどうかは、モデルがツールを呼ぶかどうかで決まる。撮っただけで添え忘れた画像は返らない。エージェントの指示（AGENTS.md）で使い方を書く。
- 受け渡しの場所は、Pi の bash からも書ける。ツールを通さずにファイルを置いても、ホストの検査を通れば返る。検査で守るのは形式と上限であり、中身の正しさではない。
- 呼び出し元は、保持期間のうちに取り込む必要がある（ADR 0001 の Consequences と同じ）。
- 取得先の URL は `publicUrl` の origin の直下になる。エージェントごとにホスト名を分けて Ingress で出す形には合うが、
  1 つのホスト名のパスで振り分ける形には、そのままでは合わない（A2A の受け口も origin の直下で受けている）。
