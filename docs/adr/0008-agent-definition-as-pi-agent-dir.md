# 0008. エージェントの定義は Pi の agentDir で持ち、ログインはエージェントごとに分ける

- Date: 2026-09-22
- Status: Accepted

## Context

ADR 0002 で、汎用ホストのエージェントごとの違いは AGENTS.md・スキル・マウント・秘密・モデルの設定だけにすると決めた。
ADR 0007 で、汎用ホストは素の Pi を子プロセスで動かすことにした。ここでは、エージェントの定義をどの形で持ち、どう配るかを決める。

Pi は、1 つの設定の置き場（agentDir）に AGENTS.md・設定・認証情報・セッションを持つ。置き場は環境変数で指定できる。
Pi には、拡張・スキル・プロンプト・テーマをまとめて配る Pi パッケージの仕組みがあり、設定から版を固定して読み込める。
AGENTS.md・設定・認証情報は Pi パッケージには入らない。

エージェントのモデルは、ChatGPT Plus のサブスクリプション経路を基本とし、なつみとは別にログインする（ADR 0002）。
Pi は、ログインの認証情報を refresh のたびに書き換える。ログインには、ブラウザを使う方式と、headless で使える device code の方式がある。

## Decision

### 1 エージェント = Pi の agentDir 1 つ

- エージェント 1 つに、Pi の agentDir を 1 つ割り当てる。独自の定義ファイルは作らない。
- agentDir の中身は、次のように配る。
  - AGENTS.md と設定は ConfigMap で配る。
  - 認証情報とセッションのファイルは、書き込める PVC に置く。
- 共通の部品（例えば門番の拡張。ADR 0009）は、fraction-agents が出す Pi パッケージにまとめる。
  各エージェントは、設定の中でこの Pi パッケージの版を固定して読み込む。

### ログインはエージェントごとに Pod の中で行う

- ログインは、エージェントごとに、そのエージェントの Pod の中で行う。Pod の中で Pi を対話で起動し、device code の方式でログインする。
- 認証情報は Pod の間で共有しない。
  - 別々のファイルで同じログインの refresh token を使い回すと、ローテーションで互いの token を失効させるためである。
- ログインの手順は、fraction-agents の README に書く。

## Consequences

- エージェントの定義が Pi の流儀そのものになる。手元の Pi で同じ agentDir を使えば、エージェントと同じ振る舞いを確かめられる。
- 共通の部品を Pi パッケージとして版で固定するので、部品を上げるときはエージェントごとに版を上げる。上げ忘れたエージェントは古い部品のまま動く。
- AGENTS.md と設定は ConfigMap なので、変更は manifest の適用で反映する。認証情報は PVC にあるので、Pod を作り直しても残る。
- エージェントを足すたびに、そのエージェントの Pod に入ってログインする手間が掛かる。ログインが切れたときも同じ手順でやり直す。
- ログインがエージェントごとに分かれるので、1 つのエージェントの失効が他のエージェントに及ばない。その代わり、Plus の上限はすべてのエージェントとなつみで分け合う（ADR 0002）。

## 実装での注記（2026-09-22）

### Pi パッケージの版は image の版で固定する

- 「各エージェントは、設定の中でこの Pi パッケージの版を固定して読み込む」を改める。Pi パッケージは汎用ホストの image に入れ、
  各エージェントは settings.json の `packages` に image の中のパス（`/opt/fraction-agents/pi-package`）を書いて読む。
  パッケージの版は、image の版と同じになる。
- 理由は次のとおり。
  - Pi パッケージは、このリポジトリのルートではなく `pi-package/` にある。Pi の `git:` のソースはリポジトリのルートを読むので、
    tag を指して版を固定することができない。
  - パッケージを使うのは、いまは汎用ホストの image の中の pi だけである。image の版で固定すれば、ホストとパッケージの組み合わせが 1 つに決まる。
- パッケージを npm に出すか、別のリポジトリにすれば、settings で版を書けるようになる。
  手元の Pi でも使いたくなったら、そうする。
- Consequences の「部品を上げるときはエージェントごとに版を上げる」は、「image を上げると、その image で動くすべてのエージェントの部品が上がる」に読み替える。
  エージェントごとに部品の版を分けたいときは、エージェントごとに image の版を分ける。
