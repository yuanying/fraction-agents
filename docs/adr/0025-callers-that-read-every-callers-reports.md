# 0025. 設定に挙げた呼び出し元には、機械の口で他の呼び出し元のレポートも読ませる

- Date: 2026-10-25
- Status: Accepted

## Context

汎用ホストが保存したレポート（ADR 0020）は、機械の口（`/reports` の HTTP、共通のスキルの `report get`・`report list`）では持ち主にだけ返る。
持ち主は、その Task を送った呼び出し元の ServiceAccount である。他の呼び出し元のレポートは、知らない ID と同じ 404 になる。
すべての呼び出し元のレポートを見られるのは、GitHub のログインで本人と分かる人用のページ（ADR 0021）だけである。

本人は、なつみ（`system:serviceaccount:natsumi:natsumi`）が頼んだレポートを、本人の Claude から読みたい。
本人の Claude は別の ServiceAccount で呼ぶので、なつみのレポートは 404 になる。
人用のページを開けば URL の末尾に ID が見えるが、その ID を Claude に渡しても機械の口では取れない。

なつみも本人の Claude も、本人のための呼び出し元である。人用のページでは、本人はどちらのレポートも読める。

## Decision

### 読むだけを、設定に挙げた呼び出し元に広げる

- 設定の `reports` に `readAllCallers` を足す。値は、すべての呼び出し元のレポートを読める呼び出し元の並びで、`allowedCallers` と同じく ServiceAccount の完全な名前で書く。
  - `allowedCallers` に無い名前は設定の誤りとして、起動時に断る。受け付けない呼び出し元は、何も読めないからである。
  - 無い・空のときは、今と同じく持ち主にだけ返す。
- ここに挙げた呼び出し元は、機械の口で、他の呼び出し元のレポートも次のとおりに扱える。
  - `GET /reports` は、すべての呼び出し元のレポートを返す。新しい順で、自分のものと他の呼び出し元のものを分けない。
  - `GET /reports/<ID>.md` と `GET /reports/<ID>.html` は、持ち主を問わずに返す。
- 人用のページの URL の末尾（`reports/<ID>`）は taskId なので、そのまま `report get` に渡せる。
- 誰を挙げるかは環境の overlay（ADR 0010）で決める。このリポジトリの既定には誰も書かない。

### 消すのは今どおり持ち主だけ

- `DELETE /reports/<ID>` は、`readAllCallers` に挙げた呼び出し元でも、自分が持ち主のレポートにしか効かない。他の呼び出し元のレポートには、今と同じく 404 を返す。
- 他の呼び出し元のレポートを消すのは、ADR 0020 のとおり、本人が `kubectl exec` で係のコマンドを使う。

### 一覧に持ち主を足す

- `GET /reports` の各要素に、持ち主（ServiceAccount の完全な名前）の `owner` を足す。他の呼び出し元のレポートが混じっても、誰のものかが分かるようにする。
- `readAllCallers` に無い呼び出し元にも足す。値はいつも自分である。欄を足すだけなので、今の呼び出し元は壊れない。
- 共通のスキルの `report list` は、`owner` があれば `<namespace>/<name>` の形で出す。`owner` を返さない古いホストには、今までの形で出す。

### 退けた案

- 係に同梱したレポートのコマンド（`report-cli`）に本文を出す `get` を足し、`kubectl exec` で読む。
  本番の Pod に入る操作を、レポートを読むたびの普段使いにしたくない。消すような、まれで重い操作に限っておく。
  また、Claude にクラスタの Pod に入る権限を持たせることになる。
- 持ち主の判定をやめ、許した呼び出し元すべてに、すべてのレポートを読ませる。
  外の文を読む係や、人ではない呼び出し元にも、本人の他の呼び出し元のレポートが見えてしまう。読めるのは、本人のための呼び出し元に限る。
- 人用のページの口（ADR 0021）を機械にも開く。人用の listener は gated のアサーションで確かめる前提で、機械の Bearer の認証を持たない。口を二つの認証で兼ねさせない。

## Consequences

- 本人の Claude から、なつみなど本人の他の呼び出し元が頼んだレポートを、人用のページの URL の末尾の ID で読める。人用のページで読める範囲と同じである。
- `readAllCallers` に挙げた呼び出し元の token が漏れると、自分のレポートだけでなく、すべての呼び出し元のレポートが読まれる。挙げるのは、本人が手元で使う呼び出し元に限る。
- 消す権限は広げないので、token が漏れても、他の呼び出し元のレポートは消されない。
- `readAllCallers` に挙げた呼び出し元が一覧を取ると、他の呼び出し元のレポートも並ぶ。古いものを消すつもりで ID を拾うと、他の呼び出し元のものには 404 が返る。消せるかは `owner` で分かる。
