# 0015. 返事の取り決めを A2A の拡張にし、submit_reply で受けた返事を DataPart で返す

- Date: 2026-10-05
- Status: Accepted

## Context

汎用ホスト（ADR 0007）は、Pi の最後の返事の文を `response` という名前の artifact の TextPart で返している。
画像だけは、ADR 0012 で別の artifact にした。

秘書のなつみは、長い返事（調べものの結果など）で文脈が膨らむことに困っていた。
なつみの側では、外のエージェントの返事をファイルに置き、要約だけを読み、要るときに節を 1 つずつ読む形に変える
（natsumi の ADR 0069「外のエージェントの返事は /sources にファイルで置き、sources_updated で知らせる」）。
そこで決まったのは次のことである。

- 返事の DataPart の中身は、相手によらず共通の形 1 つにする。`summary`（3 行以内）、`sections`（`title` と Markdown の `body` の並び）、`sources`（`title` と `url` の並び）。
- 形の取り決めは、版を含む拡張の URI と JSON Schema で結ぶ。文書と JSON Schema は fraction-agents に置き、URI を Agent Card に書く。
- なつみは、拡張を名乗る相手にだけ DataPart を求める。受け取ったら JSON Schema で検証し、合わなければ文章の返事として扱う。
  DataPart に対応していない相手の返事は、なつみのサーバーが Markdown の見出しで節に切り、先頭の段落を要約にする。

この ADR は、その取り決めの fraction-agents の側を決める。

- A2A 1.0 の拡張は、Agent Card の `capabilities.extensions` に URI と説明と `required` を書いて名乗る。
  呼び出し元は、要求の service parameter `A2A-Extensions`（JSON-RPC over HTTP では HTTP ヘッダ）に URI を並べて有効にする。
  使っている `@a2a-js/sdk` 1.2.0 は、Agent Card に無い URI を要求から落とし、有効にした拡張を応答の `A2A-Extensions` ヘッダで返す。
- 返事を書くのは Pi の中のモデルである。ホストは、モデルの最後の文から構造を読み取れない。
- 画像の受け渡し（ADR 0012）では、Pi パッケージのツールがホストの決めた場所にファイルを置き、タスクの完了時にホストが引き取る形をとった。

## Decision

### 取り決め

- 拡張の URI は `https://github.com/yuanying/fraction-agents/tree/main/docs/extensions/reply/v1` とする。
  - このリポジトリの、取り決めの文書のディレクトリを指す。開けば文書が読める。
  - 版は末尾の `v1` で表す。形を変えるときは `v2` を別の URI で出し、v1 は変えない。
- 文書は `docs/extensions/reply/v1/README.md`、JSON Schema（draft 2020-12）は同じディレクトリの `reply.schema.json` に置く。
- 形は natsumi の ADR 0069 の 3 つの欄だけとし、ほかの欄を許さない。3 つとも必須で、`sections` と `sources` は空でよい。
- 上限を決める。要約は 500 文字・3 行まで、節は 50 まで（題は 1 行 200 文字、本文は 50000 文字まで）、出典は 100 まで（題は 1 行 300 文字、URL は `http`・`https` で 2000 文字まで）。
  - 退けた案: 上限を決めない。受け取る側が、大きさの見当を付けられない。

### 名乗り方と有効にし方

- 汎用ホストは、どのエージェントの Agent Card にもこの拡張を書く。`required` は `false` とする。
  - 拡張を実装しているのはホストであり、エージェントの定義によらない。Pi パッケージを読むエージェントなら、どれも返事を出せる。
  - 返事を出さないエージェントでも、名乗ってよい。有効にした呼び出し元には、文章だけが返る（下の「返事が無いとき」）。
- 拡張は、`A2A-Extensions` に URI を書いた要求でだけ有効にする。
  - `acceptedOutputModes` に `application/json` があるだけでは有効にしない。`application/json` は形を決めないので、DataPart を返しても読めるとは限らない。
  - 答えを待っている Task（`INPUT_REQUIRED`）は、Task を始めた要求か、答えの要求のどちらかで有効になっていれば、有効として扱う。
  - 有効にした要求の応答には、SDK を通して `A2A-Extensions` ヘッダに URI を返す。DataPart が付いたかは artifact で分かる。

### 返し方

- 拡張が有効で、エージェントが取り決めの形の返事を出したとき、`response` の artifact の parts を 2 つにする。
  - 1 つ目は今までどおりの TextPart。2 つ目は DataPart で、`data` が返事、`mediaType` が `application/json`。
  - artifact の `extensions` に URI を書く。
  - 退けた案: DataPart を別の artifact にする。返事が 2 つの artifact に分かれ、どちらが本体か取り決めが要る。
  - 退けた案: DataPart だけを返す。対応していないところ（ログ、`a2a-cli` の表示）で読めなくなる。
- エージェントが返事を出したときは、TextPart の文章を、その返事を Markdown にしたものにする。拡張を有効にしていない呼び出し元にも、同じ文章を返す。
  - 1 つ目の段落が要約、節ごとに `## <題>` の見出しと本文、最後に `## Sources` と出典のリンクの並び。
  - 文章だけを読む呼び出し元にも、返事の全部が届く。なつみの「見出しで節に切り、先頭の段落を要約にする」読み方で、ほぼ同じ形に戻る。
  - モデルの最後の文は使わない。モデルには、返事を出した後は短い 1 行で終えるように言う。同じ中身を 2 度書かせない。
  - 退けた案: モデルの最後の文を TextPart にし、返事は DataPart にだけ入れる。モデルが同じことを 2 度書き、2 つが食い違いうる。
- 画像の artifact（ADR 0012）は、今までどおり `response` の後に足す。

### 返事の出し方

- Pi パッケージに、返事を出すツール `submit_reply(summary, sections?, sources?)` を足す。
  - ホストは context ごとに返事のファイル `<dataDir>/replies/<contextId>.json` を決め、環境変数 `FRACTION_AGENTS_REPLY_FILE` で Pi に渡す。
    ツールは返事を検査し、書き終えてから置き換える形でファイルに置く。
  - 2 度呼べば、後の返事で置き換える。
  - 環境変数が無いとき（ホストの外）は、ツールを出さない。
  - 退けた案: 画像と同じ outbox に置く。outbox は画像の受け渡しの形で、引き取りの規則が違う。
  - 退けた案: モデルの最後の文を JSON にさせる。文と JSON が混ざり、モデルが形を崩しやすい。ツールなら、呼んだ時点で検査の結果を返せる。
- 検査は 2 か所で同じ形に対して行う。
  - ツールは、呼ばれた時点で検査し、だめなら理由をモデルに返して書かない。
  - ホストは、タスクの完了時にファイルを読んでもう一度検査する。ツールを通さずに置かれたファイルも同じ検査を通る。
  - 検査のコードは Pi パッケージの `lib/reply.ts` に 1 つだけ置き、ホストもそれを使う。依存を持たないので、ホストは Pi の外で動かせる。
  - テストで、同じ例の並びを JSON Schema と検査のコードの両方に通し、結果が一致することを確かめる。
  - 退けた案: ホストで JSON Schema の検証器を使う。ホストの依存が増え、Pi の中でも同じ検証器を解決できるとは限らない。
- 返事が無いとき、または検査に通らないときは、モデルの最後の文を TextPart で返す。DataPart は付けない。検査に通らなかった理由はホストのログに残す。
- `FAILED`・`CANCELED` で終わった Task、答えを待っているうちに止めた Task の返事は捨てる。次の Task には持ち越さない。
  ホストの起動時にも、残っている返事を捨てる。

### 指示

- 調べもの係（ADR 0013）の AGENTS.md を、答えを `submit_reply` で出す形に直す。読めなかったページと添えた画像の名前は節に書く。
- Wiki 管理人とカレンダー係は、Pi パッケージを読んでいるのでツールは使える。指示はまだ変えない。返事は今までどおり文章で返る。

## Consequences

- 調べもの係の返事は、拡張を有効にした呼び出し元には DataPart でも届く。なつみは、要約と節を Markdown の解析なしに置ける。
- 拡張を有効にしない呼び出し元（今のなつみ、`a2a-cli`、Claude の補助スクリプト）にも、返事を Markdown にした文章が届く。今までの最後の文とは書きぶりが変わる。
- 返事を出すかどうかは、モデルがツールを呼ぶかどうかで決まる。呼び忘れれば、最後の文だけが返る。呼んだ後に最後の文へ追記したことは、呼び出し元に届かない。
- 返事のファイルは、Pi の bash からも書ける。検査で守るのは形と上限であり、中身の正しさではない。
- 文章は `## Sources` の見出しを英語で出す。返事の言語によらず同じ見出しになる。
- 検査のコードがホストと Pi パッケージで共有になるので、image の build でそのファイルもホストに入れる。
- 形を変えるときは v2 を出すことになり、v1 を名乗る相手と受け取る側を両方とも直すまで、両方の版を扱う必要がある。
