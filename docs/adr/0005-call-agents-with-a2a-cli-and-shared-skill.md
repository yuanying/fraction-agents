# 0005. Claude・Codex・Pi からは公式の a2a-cli と共通のスキルで呼ぶ

- Date: 2026-09-22
- Status: Accepted（ADR 0001 の「Claude と Codex のための橋」を置き換える）

## Context

ADR 0001 は、Claude と Codex が A2A を直接話せないため、MCP のサーバーを 1 本作って A2A への橋にすると決めていた。
橋が持つ操作は、エージェントの一覧・依頼の送信・結果の取得だけの予定だった。

実装に入る前に、次のことが分かった。

- A2A 1.0 に対応し、保守されている MCP の橋は見つからなかった。作るなら自作になる。
- A2A の公式の CLI（[a2aproject/a2a-cli](https://github.com/a2aproject/a2a-cli)）があり、A2A 1.0 に対応している。
  bearer token での認証、送信だけしてすぐ戻る使い方、Task の結果を待って取る使い方を持つ。
- 汎用ホストの runtime である Pi（ADR 0002）は MCP を持たない。外の道具は CLI とスキルで使う流儀である。
- MCP のツールの呼び出しには時間の上限があり、長い Task の結果を待つには向かない。橋は常駐するサーバーでもあり、運用するものが増える。

エージェントを呼ぶ側は、Claude と Codex に加えて、将来は Pi で動くエージェントやなつみもありうる。

## Decision

### MCP の橋は作らない

- ADR 0001 の「MCP のサーバーを 1 本作り、A2A への橋にする」は採らない。
- Claude・Codex・Pi は、公式の `a2a-cli` を CLI として使ってエージェントを呼ぶ。
  - token は `a2a-cli` の認証の設定（環境変数 `A2ACLI_AUTH`）で渡す。token は ServiceAccount の token である（ADR 0003）。

### 共通のスキルを配る

- fraction-agents は、エージェントを呼ぶための共通のスキルを 1 つ配る。
  - スキルが受け持つのは、エージェントの名前と URL の一覧、token の読み込み、`a2a-cli` の使い方である。
  - スキルは Agent Skills の形式で書き、Claude・Codex・Pi のどれからも読めるようにする。
- スキルはエージェントごとに作らない。エージェントを増やしても、スキルは 1 つのままにする。
- このリポジトリは public なので、実際の URL と token はリポジトリに書かない。スキルがそれらを呼び出し元の手元のどこから読むかは、実装で決める。

## Consequences

- 常駐する橋が無くなり、運用するものが減る。橋の自作と、A2A の版への追従も要らなくなる。
- MCP のツールの時間の上限に縛られない。長い Task は、送信だけしてすぐ戻り、後から結果を取りに行く形で扱える（ADR 0007）。
- Claude・Codex・Pi が同じ CLI と同じスキルでエージェントを呼べる。呼び出し元の種類ごとに作り分けなくてよい。
- `a2a-cli` の版と A2A の版の追従は、公式の CLI の側に任せることになる。CLI が追従しないと、呼び出し元が新しい版を使えない。
- CLI の実行には、呼び出し元の側でシェルを使える必要がある。シェルを使えない呼び出し元には、別の手段が要る。
- 成果物の URI に token が付く場合、CLI の出力を通じて呼び出し元のトランスクリプトに残る。
