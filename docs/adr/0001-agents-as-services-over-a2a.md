# 0001. エージェントを独立したサービスとして飼い、A2A で話す

- Date: 2026-09-22
- Status: Accepted（「Claude と Codex のための橋」は ADR 0005 で置き換えた。本文の MCP の橋への言及は ADR 0005 のとおり読み替える。「成果物は URI で渡す」の形は ADR 0012 で決めた）

## Context

本人は、デスクトップ常駐のアシスタント「なつみ」（[yuanying/natsumi](https://github.com/yuanying/natsumi)）と、
コーディングに使う Claude や Codex を使っている。これに加えて、特定の仕事だけをするエージェントを増やしたい。
最初に考えているのは次のものである。

- LLM Wiki の管理人（取り込み・問い合わせ・更新）
- ウェブ検索
- Stable Diffusion による画像生成

なつみの ADR 0012 は、同僚の AI をなつみのサーバーの中に置き、同僚どうしは直接つながらない形を決めていた。
この形では、同僚を使えるのはなつみだけになる。本人が Claude から Wiki 管理人に直接頼むことはできず、
同僚を増やすたびになつみのサーバーが大きくなる。

本人は、Kubernetes のクラスタでエージェントをたくさん飼いたいと考えている。

## Decision

### 独立したサービスとして飼う

- 各エージェントは、Kubernetes のクラスタに独立したサービスとして立てる。
- なつみも Claude・Codex も、同じエージェントの同じ口を直接呼ぶ。なつみを経由させない。
- なつみが「ハブ」であるのは、本人の窓口という意味だけとする。エージェントへの経路をなつみに集めるという意味ではない。

### 話し方は A2A

- エージェントとのやり取りには A2A（Agent2Agent Protocol）を使う。
  - 各エージェントは Agent Card で自分の能力と認証の方式を示す。
  - 依頼はメッセージの送信で受け、Task として状態（受付・処理中・入力待ち・完了・失敗など）を持つ。
  - 非同期の依頼、後から結果を取りに来る形、Task の状態が、なつみの単一の思考ループ（なつみの ADR 0008）と合うので A2A を選ぶ。
- A2A の版は改訂が続いている。実装に入る時点の最新版と、公式の SDK の版を確かめてから使う。
- 結果の受け取り方（ストリーム、push 通知、取りに行く）のどれを使うかは、まだ決めていない。

### 呼び出しの向き

- エージェントは末端とする。エージェントは他のエージェントもなつみも呼ばない。
  - エージェントどうしの呼び出しが必要になったら、その組ごとに個別に許す。
- なつみは A2A のクライアントとしてエージェントを呼ぶ。なつみ自身も受け口（Agent Card）を持つが、それはなつみの側の決定であり、このリポジトリの範囲外とする。
- 信頼の境界が要るのは、エージェントの返事を受け取るなつみの側だけになる。エージェントは誰も呼ばないので、エージェントの出力が他の依頼の引き金になる道がない。

### 成果物は URI で渡す

- 画像などの成果物は、エージェントが自分の volume に置き、取得できる URI を A2A の artifact として返す。
  - URI の取得にも認証を掛ける（ADR 0003）。
  - 受け取った側が、必要なら自分の領域に取り込む。
  - 保持期間はエージェントごとに決める。
- 大きなデータを A2A のメッセージに埋め込まないので、呼び出し元に取り込むかどうかを選ばせられる。

### Claude と Codex のための橋

- Claude や Codex は A2A を直接話せない。このため、MCP のサーバーを 1 本作り、A2A への橋にする。
- 橋が持つ操作は、エージェントの一覧・依頼の送信・結果の取得だけとする。
- 橋はエージェントごとに作らない。エージェントを増やしても橋は 1 本のままにする。

### このリポジトリに置くもの

- A2A の共通部分、汎用ホスト（ADR 0002）、MCP の橋、各エージェントの定義、Kubernetes の manifest を 1 つのリポジトリにまとめる。
- なつみは A2A の SDK でエージェントと話すだけで、このリポジトリのコードには依存しない。
- リポジトリは public とする。実データと秘密は Kubernetes の Secret と volume に置き、リポジトリには入れない。

### 最初に作るもの

- 最初は、エージェントの側だけを作る。汎用ホスト、Wiki 管理人、認証（ADR 0003）、MCP の橋である。
  この段階で本人と Claude が使えるようになり、なつみには触れない。
- なつみの A2A クライアント、なつみの受け口、なつみの Kubernetes への移行は、その後になつみの側で進める。

### 範囲外

- 外に作用する同僚（Slack への投稿役のポッポさん、将来の予定の同僚）は、なつみのサーバーの中に残す（なつみの ADR 0012）。
  A2A に載せるのは、読み取りと生成が中心の道具的なエージェントである。
  なつみの ADR 0012 の「同僚はサーバーの中、同僚どうしは直接つながらない」は、外に作用する同僚に限った話として読む。
- なつみがエージェントの返事をどう扱うか（イベントの種類、記憶への残し方、上限、Mac に見せるか）は、なつみの側で決める。

## Consequences

- 本人・Claude・なつみが同じエージェントを使える。なつみを通さずに Wiki 管理人や画像生成に頼める。
- エージェントを足しても、なつみのサーバーは変わらない。なつみの側に要るのは、宛先の追加だけになる。
- エージェントごとに Pod・volume・Secret・認証の設定が増え、運用するものが増える。
- A2A の版が上がると、共通部分と MCP の橋、なつみのクライアントの追従が要る。
- エージェントが誰も呼ばないので、エージェントを経由した依頼の連鎖は起きない。その代わり、複数のエージェントを組み合わせる仕事は、呼び出し元（本人・Claude・なつみ）が組み立てる。
- 成果物がエージェントの volume に残るので、保持期間を過ぎた URI は取れなくなる。長く残したいものは受け取った側が取り込む。
