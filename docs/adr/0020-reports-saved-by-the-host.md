# 0020. 返事をレポートとして汎用ホストが保存し、Markdown と HTML で取らせる

- Date: 2026-10-15
- Status: Accepted（「レポートを返すのは持ち主にだけ」は、読むことに限って ADR 0025 で改めた。設定に挙げた呼び出し元は、他の呼び出し元のレポートも取れ、一覧に並ぶ）

## Context

deep research の係（ADR 0022）は、調べた結果を長いレポートにして返す。本人と決めたことは次のとおりである。

- レポートの正本は Markdown にする。HTML はホストが決まった型で変換する（目次・表・コードのハイライト・Mermaid の図）。モデルに HTML を書かせない。
  外から来た文の影響を受けるモデルに HTML を自由に書かせると、script などが入りうるからである。
- なつみには、レポートの本文を返事の `sections` にそのまま入れて渡す。natsumi の側は変えない。
- Claude・Pi・Codex・なつみは、今の A2A と同じ token（ADR 0003）で Markdown と HTML を取れる。共通のスキル（ADR 0005）に取り方を足す。
- 人はブラウザで GitHub のログインを通して見る。その口は ADR 0021 で決める。
- レポートは消さない（手で消すまで残す）。backup に入れる。clone などの作業領域は入れない。
- A2A でも消せる。消せるのは、自分が頼んだレポートだけである。他の呼び出し元のレポートは、知らない ID と同じに扱う。
  他の呼び出し元のレポートを本人が消すときは、`kubectl exec` で係のコマンドを使う。

汎用ホストには、返事を保存する仕組みがまだ無い。

- 返事の取り決め（ADR 0015）の返事は、Task が完了したときに `response` の artifact の文（返事を Markdown にしたもの）と DataPart で返る。Task の記録は context と一緒に `sessionRetentionSeconds`（既定 7 日）で消える。
- 画像の成果物（ADR 0012）は、ホストが PVC に置き、持ち主を記録して、同じ token で取らせている。期限が来たら消す。
- 返事は、どの係でも `submit_reply` で出せる。返事の形は係によらない。

## Decision

### 汎用ホストの機能にする

- レポートは、汎用ホストの機能とし、設定で係ごとに有効にする。今は deep research の係だけが有効にする。
  - レポートの元は返事の取り決めの返事であり、係の中身によらない。ほかの係でも、設定を書けば同じように残せる。
- 設定に `reports` を足す。無ければ機能は無く、今の係は変わらない。

### 何をレポートにするか

- `reports` が有効な係で、Task が `completed` になり、返事の取り決めの返事が出ていたとき、その返事を 1 つのレポートとして保存する。
  - 時間の上限（ADR 0019）で途中までを返した Task も、返事が出ていればレポートにする。途中までであることを記録する。
  - 返事が出なかった Task、`failed`・`canceled` で終わった Task は、レポートにしない。
- レポートの ID は、その Task の taskId とする。呼び出し元は手元にある taskId でレポートを取れる。
- 同じ context の続きの依頼（「続けて」など）は、別の Task なので別のレポートになる。前のレポートは残る。
  続きのレポートが前の分も含んだ全体になるようにするのは、係の指示（AGENTS.md）の仕事である。
- レポートの正本は、ホストが返事を Markdown にした文（`response` の artifact の文と同じもの、ADR 0015）とする。
  - 途中までのレポートには、先頭にホストが決まった文で「時間の上限で途中まで」の注記を足す。
  - 返事の節の中の、ホストが足す「レポート」の節（下の「返事に URL を入れる」）は、レポートには入れない。
- 題は、返事の `summary` の 1 行目とする（長ければ切る）。係の指示で、`summary` の 1 行目を何のレポートかが分かる文にさせる。
  - 退けた案: 依頼の文の 1 行目を題にする。続きの依頼では「続けて」が題になる。

### 置き場と記録

- レポートは、設定のディレクトリ（既定 `<dataDir>/reports`）に置く。係の PVC の中で、ほかのものと分かれたディレクトリになる。
- 1 つのレポートは、本文の Markdown のファイルと、記録の JSON のファイルの 2 つで表す。記録は ID・持ち主・context・題・作った時刻・途中までか、である。
  - 書くときは、一時ファイルに書いて置き換える。本文を書いてから記録を書き、記録があるものだけをレポートとして扱う。書きかけは見えない。
  - 一覧はディレクトリの記録から作る。数は手で消すまで増え続けるが、人が頼む数なので、起動時に読んで持つ。
  - 退けた案: 記録を `state.db`（SQLite）に持つ。backup をレポートのディレクトリだけにすると記録が欠ける。動いている SQLite をファイルの写しで取ると、壊れた写しになりうる。
- このディレクトリだけを backup の対象にできる。戻すときは、ディレクトリを写し戻してホストを起動し直せばよい。backup の置き方は環境の overlay の側で決める（ADR 0010）。
- 持ち主は、その Task を送った呼び出し元（ServiceAccount の名前、ADR 0003）とする。context が保持期間で消えても、レポートと持ち主は残る。
- 消すのは、下の「消し方」だけである。期限で消すことはしない。

### 機械の取り方

A2A と同じ listener、同じ認証（ADR 0003）で、次の口を出す。token が無い・違うときは 401、許していない ServiceAccount は 403 である。

| 口 | 中身 |
|---|---|
| `GET /reports` | 自分が持ち主のレポートの一覧。新しい順で、ID・題・作った時刻・途中までか |
| `GET /reports/<ID>.md` | レポートの本文の Markdown（`text/markdown; charset=utf-8`） |
| `GET /reports/<ID>.html` | レポートを HTML にしたもの（下の「HTML にする」） |
| `DELETE /reports/<ID>` | レポートを消す。消せたら 204 |

- レポートを返す・消すのは、持ち主にだけである。他の呼び出し元と知らない ID には、同じ 404 を返す（ADR 0012 と同じ）。
  - ADR 0025 で改めた: 設定の `reports.readAllCallers` に挙げた呼び出し元には、他の呼び出し元のレポートも返し、一覧にも並べる。一覧の各要素には持ち主を足した。消すのは今も持ち主にだけである。
- 応答には `Cache-Control: private, no-store` と `X-Content-Type-Options: nosniff` を付ける。
- 共通のスキル（`skills/fraction-agents`）に、レポートを取る・一覧を見る・消すコマンド（例 `report get <taskId> --format md|html`、`report list`、`report delete <taskId>`）を足す。足すのはスキルの作業単位で行う。

### 消し方

- 呼び出し元は、上の `DELETE` で、自分が持ち主のレポートだけを消せる。消すと本文と記録がなくなり、人用のページ（ADR 0021）も 404 になる。Task の記録はそのまま残り、保持期間で消える。
- A2A の依頼（モデルに頼む形）では消さない。消すのは HTTP の口だけである。
  - モデルに消す道具を持たせると、調べものの中で読んだページに仕込まれた指示で、呼び出し元のレポートを消されうる。HTTP の口なら、消すのは呼び出し元のコードの判断だけで決まり、Plus の枠も使わない。
  - このため、`ask_agent` で自然文の依頼だけを送るなつみからは消せない。要るようになったら、そのときに考える。
- 他の呼び出し元のレポートを消すときは、本人が `kubectl exec` で係の Pod に入り、ホストに同梱したレポートのコマンドで一覧を見て消す。コマンドは持ち主を問わない。使い方は README に書く。
- 退けた案: 消すのを `kubectl exec` のコマンドだけにする。呼び出し元が自分で片付けられない。

### HTML にする

- HTML はホストが Markdown から決まった型で作る。モデルは HTML を書かない。HTML は保存せず、取られるたびに作る。型を直せば、古いレポートも新しい型で出る。
- 型が出すもの: 題・作った時刻・依頼した呼び出し元・途中までの注記、見出しから作る目次、表、コードのハイライト（ホストの側で色を付け、script を要らなくする）、Mermaid の図。
- Markdown の中の HTML は使えなくする。生の HTML は文として出す。そのうえで、できた HTML を許可リストで無害化する（使ってよい要素と属性だけを残す）。二重にするのは、変換器の誤りで抜けるものを残さないためである。
- リンクは `http`・`https`・ページの中の見出しへのものだけを残す。外へのリンクには `rel="noopener noreferrer"` を付ける。
- 外の画像は読み込まない。Markdown の画像は、画像へのリンクとして出す。ページを開いただけで、外のサーバーに見たことが伝わらないようにする。
- HTML は CSS を中に持ち、ほかのファイルを要らない 1 つの文書にする。保存して手元で開いても同じに見える。
  - ただし Mermaid の図を描く script は大きいので、文書に入れない。機械が取る HTML（`/reports/<ID>.html`）では、図は Mermaid の文のまま出る。図を描くのは人用のページ（ADR 0021）だけである。
- 文書の中に Content Security Policy を `meta` で書く。script を使わず、外のものを何も読み込まない方針にする。保存したファイルを開いたときにも効かせるためである。人用のページは ADR 0021 で応答のヘッダにも付ける。
- Markdown の変換器・ハイライト・無害化に使うものは実装で決める。

### 返事に URL を入れる

- 人用の口の公開 URL（ADR 0021 の `reports.web.publicUrl`）が設定されていれば、ホストは、レポートにした Task の返事の最後に「レポート」の節を足し、人用のページの URL を書く。
  - ホストが足すので、モデルは URL を知らなくてよい。返事の文と DataPart の両方に入る。
  - 返事の節が上限（50）に達していれば足さない。係の指示で、節を 49 までにさせる。
- 機械は taskId でレポートを取れるので、機械の取得先は返事に書かない。

### 実装で決めたこと

- Markdown の変換は markdown-it（生の HTML を使わない設定）、ハイライトは highlight.js（ホストで `span` の class を付け、色は文書の CSS で付ける）、無害化は sanitize-html にした。
- 一覧はディレクトリの記録から作り、読んだ記録は持っておく。ディレクトリの中の名前は取るたびに読み直す。`kubectl exec` のコマンドが消したレポートを、ホストを起動し直さずに 404 にするためである。
- 見出しの ID は `section-<連番>` にした。モデルが書いた見出しの文を ID に使わない。
- 題は 120 文字で切る。
- 返事に足す節の題は「レポート」で、本文は人用のページの URL（`<publicUrl>reports/<ID>`）だけである。
- 機械の一覧（`GET /reports`）にページ送りは付けない。人が頼む数の規模である。
- `kubectl exec` のコマンドは `node /app/dist/src/report-cli.js list|delete <ID>` で、ホストと同じ設定ファイルを読む。

## Consequences

- deep research の係の返事が、Task の保持期間を過ぎても、同じ token で取れ、ブラウザでも見られる。なつみの側は変わらない。
- ほかの係も、設定を書くだけでレポートを残せる。
- レポートは消さない限り増え続け、PVC を使い続ける。係の PVC の容量は、レポートの増え方を見て決める。
- 消す口が HTTP だけなので、消せるのはスキルなどのコードを持つ呼び出し元だけになる。
- 同じ調べものの続きは、別のレポートとして並ぶ。どれが最新かは一覧の時刻で分かる。古いものは呼び出し元が消す。
- 題がモデルの書いた `summary` から来るので、題の良し悪しは係の指示に頼る。
- 機械が取る HTML では Mermaid の図が描かれない。図を見たいときは人用のページで開く。
- HTML を取られるたびに作るので、取るたびに変換の手間がかかる。人が頼む数の規模では問題にならない。
- 返事は外から来た文を含む。無害化と CSP で script を止めても、文の中身（誤った情報や誘導の文）はそのまま出る。
